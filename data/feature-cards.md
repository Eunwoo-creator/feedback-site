# 내 기능 카드

> 기능 추가 ②(혼자)에서 고를 수 있는 예시입니다. 직접 정해도 됩니다. 어떤 기능이든 **PRD에 한 줄 → Spec 갱신 → 티켓 → 구현 → 확인** 순서로 갑니다. 15분 안에 끝낼 수 있게 작게 정합니다.

| 카드 | 한 줄 설명 | PRD에 적을 한 줄 예시 | 난이도 |
|---|---|---|---|
| ⭐ 칭찬 스티커 | 선생님이 피드백에 스티커 하나를 고르면 학생 화면에 크게 보인다 | "선생님은 피드백에 칭찬 스티커 하나를 붙일 수 있다" | 쉬움 |
| ⏰ 제출 마감 알림 | 과제에 마감 시각을 정하면 학생 화면에 남은 시간이 보인다 | "과제에는 마감 시각이 있고, 학생은 남은 시간을 본다" | 보통 |
| 💌 선생님 응원 한마디 | 학생 화면 맨 위에 선생님이 정한 오늘의 한마디가 보인다 | "선생님은 학생 화면 맨 위에 오늘의 한마디를 띄울 수 있다" | 쉬움 |
| 🙂 학생 기분 체크 | 제출할 때 오늘 수업 기분을 이모지 3개 중 하나로 고른다 | "학생은 제출할 때 오늘 수업 기분을 고른다" | 쉬움 |
| 🔐 비밀번호를 서버로 | 선생님 비밀번호를 화면 코드에서 빼고 Vercel 환경 변수(`TEACHER_PASSWORD`)와 서버 함수에서 확인한다 | "선생님 비밀번호는 서버에서만 확인한다" | 어려움 |

> 🔐 "비밀번호를 서버로" 카드의 한계: 화면 잠금을 서버 확인으로 바꿀 뿐, 데이터베이스는 여전히 누구나 읽을 수 있습니다.

## 시작 프롬프트

```
PRD.md에 "추가한 기능" 절이 없으면 맨 아래에 만들고, 그 절에 아래 한 줄을 넣어 줘: (카드의 PRD 한 줄)
그다음 .scratch/feedback-site/spec.md에 이 기능의 구현 결정을 덧붙이고,
완료 기준이 있는 티켓 하나를 .scratch/feedback-site/issues/에 새 번호로 만들어 줘.
코드는 아직 고치지 마.
```
