# 생각 노트

기존 방탈출과 분리된 사이트. 초등학생이 수업 후 배운 내용을 자기 말로 쓰고 선생님이 차수별로 피드백함.

## 기본 질문

1. 오늘 배운 내용을 자기 말로 설명해 보세요. (필수)
2. 오늘 수업에서 재미있었거나 흥미로웠던 점에 대해 이야기해 주세요! (선택)
3. 아직 헷갈리는 점은 무엇인가요? (선택)
4. 선생님들에게 바라는 점이 있나요? (선택)

선생님은 수업별로 질문을 수정할 수 있음. 이전 답변의 질문은 당시 내용을 보존함.

## 참여와 공개 범위

회원가입 없음. 학생은 수업 코드와 이름으로 최초 참여, 12자리 개인 확인 번호 자동 발급. 복귀 시 수업 코드와 확인 번호 필요. 학생 본인과 해당 수업 선생님만 답변과 피드백 열람. 선생님은 학생 확인 번호를 조회하여 분실한 학생 본인에게 알려 줄 수 있음. 교사 화면은 수업 비밀번호로 보호.

## 수정과 보관

답변은 1차·2차·3차 등으로 모두 보관. 선생님 피드백을 읽고 다시 제출 가능. 각 차수에 피드백 저장. 수업 삭제 전 확인창, 삭제 시 이름·번호·답변·피드백·접속 세션 함께 삭제.

## 화면

밝은 파란색과 흰색 노트, 큰 글씨와 입력창. 학생은 본인 답변과 피드백, 선생님은 학생 목록과 선택한 학생의 차수별 기록을 표시.

## 사용자 이야기 (User Stories)

- 선생님은 학생의 각 차수 답변에 작성한 피드백을 AI로 다듬어 같은 입력 칸에서 검토·수정한 뒤, ‘피드백 보내기’ 또는 ‘피드백 수정 저장’ 버튼을 눌러 해당 차수의 피드백으로 전달하고 싶다.
- 선생님은 각 차수의 피드백에 칭찬 스티커 하나를 골라 학생에게 함께 전달하고 싶다.
- 선생님은 수업별 오늘의 응원 한마디를 정해 해당 수업 학생들의 화면 맨 위에 보여 주고 싶다.

## 구현 결정 (Implementation Decisions): AI 피드백 다듬기

- 대상은 현재 `feedback-site2`에 배포된 생각 노트의 `reflection-notebook-vercel2/app/Notebook.tsx`이다. 학생의 1차·2차·3차 등 모든 차수 답변에 있는 기존 피드백 입력 칸에 적용한다.
- OpenAI 호출은 `api/feedback.js`(Vercel 서버 함수) 한 곳에서만 한다. 키는 환경 변수 `OPENAI_API_KEY`에서 읽고, 모델 이름은 환경 변수 `OPENAI_MODEL`로 바꿀 수 있게 한다. 기존 생각 노트의 Next.js API와 함께 `/api/feedback`이 연결되도록 배포 구성을 확인한다.
- 생각 노트 화면(`app/Notebook.tsx`)은 `/api/feedback`만 부른다. 키는 화면 코드에 넣지 않는다. 프로젝트 맨 위 `index.html`은 생각 노트의 화면 파일이 아니므로 변경 대상에서 제외한다.
- AI 결과는 요청한 학생·차수의 피드백 입력 칸에만 임시로 넣는다. 현재 화면의 `feedback[rev.id]` 편집 상태만 바꾸고 자동으로 저장하거나 학생에게 공개하지 않는다.
- 선생님이 검토·수정한 뒤 ‘피드백 보내기’ 또는 ‘피드백 수정 저장’을 눌러야 기존 `/api/notebook`의 `feedback` 저장 동작을 통해 해당 차수에 저장되고 학생에게 보인다. 다른 학생이나 차수의 피드백은 바꾸지 않는다.
- 학생 이름은 AI에게 보내지 않는다. 서버는 기존 교사 세션과 해당 수업의 답변 차수에 대한 권한을 확인하되, OpenAI에는 선생님 피드백 초안과 현재 차수의 학생 글만 전달한다. 학생 이름과 개인 확인 번호는 전송 전에 제외하고, 다른 차수의 기록은 덧붙이지 않는다. 피드백 본문에도 이름을 넣지 않도록 안내하고, 이름이 포함되어 있으면 보내기 전에 제거하도록 요구한다.
- 요청 중 중복 호출을 막는다. 응답을 기다리는 동안 직접 수정한 내용을 뒤늦은 AI 결과로 덮어쓰지 않는다. 요청 실패 시 기존 입력과 저장된 피드백을 유지하고 재시도 안내를 보여 준다.
- 기준은 사용자의 AI 피드백 다듬기 요청과 현재 생각 노트의 실제 차수별 피드백 화면이다. 가람중학교 PRD 및 `index.html`은 이 기능의 기준으로 사용하지 않는다.

## 구현 결정 (Implementation Decisions): 칭찬 스티커와 응원 한마디

### 칭찬 스티커

- 생각 노트의 각 차수 ‘선생님의 피드백’ 입력 칸에 스티커 선택 영역을 둔다. 선택지는 ‘없음’, ‘⭐ 멋진 생각’, ‘👏 수고했어요’, ‘🌱 한 걸음 성장’이며 한 번에 하나만 고를 수 있다.
- 스티커는 해당 답변 차수의 `revisions.sticker`에 문자열 식별값(`star`, `clap`, `growth`)으로 저장한다. ‘없음’과 기존 기록의 기본값은 `null`이다. 기존 `feedback` 컬럼에는 문장만 저장한다.
- 고른 스티커는 편집 상태로 유지하고, 기존 ‘피드백 보내기/피드백 수정 저장’ 버튼을 눌러야 피드백과 함께 저장된다. 스티커만 선택하고 피드백을 비워 두는 저장은 허용하지 않는다.
- 학생은 자신의 해당 차수 피드백 옆에서 저장된 스티커를 크게 보고, 문자 설명도 함께 읽을 수 있다. 다른 차수와 다른 학생의 스티커에는 영향을 주지 않는다. 선생님은 기존 스티커를 바꾸거나 ‘없음’으로 제거할 수 있다.
- AI 다듬기는 스티커를 선택·변경·저장하지 않는다.

### 선생님 응원 한마디

- 수업 질문을 수정하는 기존 선생님 설정 영역에 ‘오늘의 응원 한마디’ 입력 칸을 추가한다. 최대 120자로 제한하고, 기본값은 빈 문자열이다.
- 수업별 `lessons.encouragement`에 저장하고 기존 수업 설정 저장 동작에 포함한다. 입력만으로 공개하지 않는다. 설정을 저장한 뒤 해당 수업의 모든 학생에게 같은 문장을 보여 준다.
- 학생 화면의 수업 제목 아래, 답변 작성·기록 영역 위에 ‘선생님의 응원’으로 표시한다. 내용이 비어 있으면 영역을 숨긴다. 빈 문자열을 저장하면 응원 한마디가 내려간다.
- 다른 수업에는 영향을 주지 않는다. 일반 텍스트로 렌더링해 입력된 HTML이나 스크립트를 실행하지 않는다.

### 저장과 권한

- 대상 코드 폴더는 `reflection-notebook-vercel2`이며, 현재 배포본의 기존 `/api/notebook` 교사 세션·수업별 권한 확인과 저장 방식을 유지한다. Supabase로 저장소를 전환하는 작업은 포함하지 않는다.
- 구현 시 실제 사용 중인 데이터베이스에 `revisions.sticker`, `lessons.encouragement`를 기본값과 함께 추가하는 멱등 마이그레이션을 작성한다. 기존 답변과 피드백은 보존한다.
- Supabase 실습 스키마에도 같은 두 컬럼을 반영하되 기존 테이블에도 적용되도록 `add column if not exists`를 사용한다. 이번 문서 작업에서는 SQL을 아직 수정하지 않는다.
- 서버에서 스티커 식별값·응원 문장 길이를 검증한다. 학생은 조회만 할 수 있고 스티커와 응원 문장을 변경할 수 없다. 수업 삭제 시 기존 관계에 따라 함께 삭제된다.
- 저장 실패 시 성공으로 표시하지 않고 입력을 유지하며, 저장 완료 전 학생 화면에는 기존 저장된 값만 보여 준다.
