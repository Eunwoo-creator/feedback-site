# feedback-site 기능 명세

## 문제

선생님은 수업 뒤 학생이 무엇을 이해했고 어디에서 헷갈리는지 확인하려고 한다. 현재 피드백 방식과 그 과정에서 겪는 어려움은 PRD에서 [미정]이며, 구현에 필요하지 않으므로 그대로 남긴다.

## 해결 방법

가상의 가람중학교 2학년 과학 「전기와 자기」 수업을 위한 시연용 사이트를 만든다. 학생은 키워드를 연결해 자신의 말로 설명하고, 선생님은 글을 읽고 피드백한다. 학생 화면에는 해당 학생 자신의 기록만 보여 주고, 선생님 화면에는 학생 목록과 각 학생의 기록을 보여 준다.

PRD에 적힌 네 장면을 이번 구현 범위로 삼는다. (AI 제안)

## 사용자 이야기

1. 학생은 개인 입장 코드로 들어가 자신의 과제와 기록을 보고 싶다.
2. 학생은 오늘 수업 이름과 키워드를 보고 무엇을 설명해야 하는지 알고 싶다.
3. 학생은 키워드를 연결한 설명을 자기 말로 작성해 제출하고 싶다.
4. 학생은 필요할 때 ‘아직 헷갈리는 점’을 함께 제출하고 싶다.
5. 학생은 제출한 설명과 헷갈리는 점을 다시 보고 싶다.
6. 학생은 피드백이 없을 때 ‘선생님이 확인 중이에요’라는 문구를 보고 싶다.
7. 학생은 선생님의 피드백을 읽고 설명을 고쳐 다시 제출하고 싶다.
8. 학생은 처음 글과 고친 글을 함께 보고 싶다.
9. 선생님은 오늘 수업 이름과 키워드를 입력하거나 수정하고 싶다.
10. 선생님은 학생의 반·번호·이름과 제출·피드백·재제출 여부를 목록에서 보고 싶다.
11. 선생님은 피드백을 기다리는 글부터 보고 싶다.
12. 선생님은 학생의 글을 열어 학생 정보, 설명, 헷갈리는 점을 확인하고 싶다.
13. 선생님은 피드백을 작성하고 저장하고 싶다.
14. 선생님은 재제출한 학생의 처음 글, 고친 글과 이전 피드백을 함께 보고 싶다.

## 구현 결정

### 파일과 화면

- 모든 화면, 화면 꾸밈과 동작은 프로젝트 맨 위의 `index.html` 하나에 담는다.
- 학생 화면과 선생님 화면은 같은 파일 안에서 바꿔 보여 준다.
- 첫 화면에 학생 입장 코드 입력과 선생님 화면 열기 버튼을 둔다.
- 선생님 화면은 관리자 화면이며, 관리자 비밀번호를 입력해야 열린다.
- 실습용 관리자 비밀번호는 `teacher-demo`로 한다.
- 관리자 비밀번호 확인 전에는 관리자 화면에 학생 글과 선생님만 보는 내용을 하나도 보여 주지 않는다. 이 규칙은 학생이 자기 코드로 입장해 자신의 기록을 보는 것과 구분한다.
- 역할을 바꿀 때 기존 화면을 숨기고, 학생 입장 코드가 확인되기 전에는 학생 기록을 보여 주지 않는다. (AI 제안)
- 학생 화면의 조회·제출·수정 대상은 입장 코드에 연결된 학생 한 명으로 제한한다.
- 등록되지 않은 코드를 입력하면 입장하지 못하고 코드를 확인하라는 문구를 보여 준다. (AI 제안)

### 학생의 제출과 수정

- 학생 화면에는 수업 이름, 키워드, 설명 작성 칸, 선택 사항인 ‘아직 헷갈리는 점’ 칸과 제출 버튼을 둔다.
- 설명 작성 칸에 키워드를 연결해 문장으로 설명하라는 안내를 둔다.
- 빈 설명은 제출할 수 없으며, 키워드 사용 여부를 자동 판정하지 않는다. (AI 제안)
- 제출 후 자신의 설명과 헷갈리는 점, 피드백 또는 대기 문구, ‘설명 고치기’ 버튼을 보여 준다.
- 처음 글은 보존하고 고친 글은 가장 최근의 것 하나만 보관한다. 다시 고치면 고친 글만 갱신한다. (AI 제안)

### 선생님의 확인과 피드백

- 선생님 첫 화면에 수업 이름·키워드 입력 및 수정 영역과 학생 목록을 둔다.
- 학생 목록에 반·번호·이름, 제출 여부, 피드백 여부, 재제출 여부를 표시한다.
- 제출 또는 재제출 후 아직 피드백하지 않은 학생을 먼저 보여 준다. 같은 상태에서는 반·번호 순으로 보여 준다. (AI 제안)
- 학생을 선택하면 학생 정보, 설명, 헷갈리는 점, 피드백 입력 칸과 저장 버튼을 보여 준다.
- 재제출한 학생은 처음 글, 고친 글과 이전 피드백을 함께 보여 준다.
- 빈 피드백은 저장하지 않으며, 저장한 피드백은 해당 학생 화면에 반영한다. (AI 제안)
- 처음 글에 대한 피드백과 최신 고친 글에 대한 피드백을 각각 하나씩 보관한다. 재제출하면 고친 글의 피드백 상태는 대기로 바꾸고, 처음 글의 피드백은 유지한다. (AI 제안)

### 저장할 내용

- 데이터베이스 없이 브라우저의 localStorage에 저장한다.
- 수업 이름과 키워드, 학생 식별 정보와 입장 코드, 처음 글과 고친 글, 헷갈리는 점, 피드백과 제출 상태를 저장한다.
- 수업은 하나만 두고, 키워드는 쉼표로 나누어 입력한다. (AI 제안)
- 처음 열 때 가상 학생 3명과 예시 답변을 넣는다. 미제출·피드백 대기·재제출 상태를 한 명씩 보여 준다. (AI 제안)
- 예시 수업 이름은 ‘전류와 자기장’, 키워드는 ‘전류, 자기장, 나침반’으로 둔다. (AI 제안)
- 첫 저장 전만 예시 데이터를 넣고, 이후에는 저장된 내용을 불러와 새로고침해도 작성한 기록을 유지한다. (AI 제안)
- 저장에 실패하면 완료로 표시하지 않고 저장하지 못했다는 문구를 보여 준다. (AI 제안)

## 확인 방법

테스트 도구를 사용하지 않는다. 사용자가 브라우저에서 아래의 화면과 동작을 직접 눈으로 확인한다.

1. 학생 코드로 들어가면 수업 이름, 키워드, 작성 칸과 제출 버튼이 보인다.
2. 설명과 헷갈리는 점을 제출하고 새로고침해도 자신의 내용이 남아 있다.
3. 다른 학생 코드로 들어가면 앞 학생의 글과 피드백이 보이지 않는다.
4. 선생님 화면에서 수업 이름과 키워드를 바꾸면 학생 화면에도 반영된다.
5. 학생 목록에 반·번호·이름과 세 가지 상태가 표시되고 피드백 대기 학생이 먼저 보인다.
6. 학생의 글을 열면 작성한 내용과 피드백 입력 칸이 보인다.
7. 피드백 저장 후 해당 학생으로 들어가면 대기 문구 대신 피드백이 보인다.
8. 학생이 글을 고쳐 재제출하면 처음 글과 고친 글이 보이고, 선생님 화면에도 재제출 상태와 이전 피드백이 보인다.
9. 잘못된 코드, 빈 설명과 빈 피드백은 처리되지 않고 안내가 보인다.
10. 선생님 화면을 열려고 하면 비밀번호 입력 화면이 보이고, 확인 전에는 학생 글과 선생님 전용 내용이 보이지 않는다.
11. 빈 비밀번호나 틀린 비밀번호로는 관리자 화면이 열리지 않으며, `teacher-demo`를 입력하면 관리자 화면이 열린다.

## 만들지 않을 것

- 학생 화면에서 다른 학생의 글과 피드백 보기.
- 위 범위에 없는 기능은 이번에 추가하지 않는다. (AI 제안)
- 데이터베이스와 테스트 도구는 사용하지 않는다.

## 참고

- 기준 문서는 현재 프로젝트 맨 위의 PRD.md이다. 백업 파일로 덮어쓰지는 않았다.
- localStorage의 기록은 같은 브라우저에서 역할을 바꾸며 확인한다. 여러 기기 사이에서 기록을 공유하는 사이트로 구현하지 않는다.
- 학생별 화면 분리는 시연 화면의 표시 규칙이며, 서버에서 실제 사용자 권한을 확인하는 구조는 아니다.
- 이 문서는 명세이며, 이번 작업에서는 사이트 구현 파일을 만들지 않는다.
